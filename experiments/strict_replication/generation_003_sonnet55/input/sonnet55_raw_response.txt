## Design

**Strategy:** the paddle chases a lead target, the ball's column plus its horizontal direction of travel. The ball moves one column per step and the paddle also moves one column per step, so the paddle can keep up. The catch rule works out as follows:

- When the ball is on row 8, the game checks the ball's current column and its next column against the paddle's column after it has moved.
- Aiming at the ball's next column (x + dx) therefore lets the paddle lag by one cell, which is the typical error from sticky actions, and still catch the ball.

**Signed error:** let `d = 2·ball_x − trail_x − paddle_x`. This equals (ball_x + dx) − paddle_x, because `dx = ball_x − trail_x`. It is a purely linear function of the input, since each cell's weight is just its column index.

**Hidden units:**
- **Layer 1, unit 0:** `tanh(6d − 3)`, which is about +1 if d ≥ 1 and −1 if d ≤ 0 (paddle needs to go right).
- **Layer 1, unit 1:** `tanh(6d + 3)`, which is about +1 if d ≥ 0 and −1 if d ≤ −1 (paddle does not need to go left).
- **Layer 2:** unit 0 and unit 1 each pass their layer-1 partner through with gain 3, to sharpen the saturation.
- **Output:**
  - right = 10·a
  - left = −10·b
  - no-op = 10·(b − a)
  - up, down and fire get a −10 bias.
  - The right action wins by a margin of about 10 when d ≥ 1.
  - No-op wins by about 30 when d = 0.
  - Left wins by about 10 when d ≤ −1.
  - Sampling is therefore almost deterministic.

I traced both starting positions by hand. In each case the paddle is in a catching position on the first descent.
