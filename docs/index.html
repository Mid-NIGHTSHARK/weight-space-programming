Experiment 5 · MinAtar Breakout

Can a language model write a useful neural network?

We tested whether language models could produce the numerical weights for a small game-playing network directly, without training feedback.

The networks controlled Breakout in MinAtar. Their scores were measured over thousands of episodes, then checked against the preserved experiment files and raw evaluation data.

Matched episodes

Statistical comparisons

Each comparison subtracts scores from episodes with the same base seed. The bootstrap interval shows uncertainty by resampling those matched pairs. The two-sided sign-flip test checks whether paired differences are centered around zero. Cohen’s dz scales the average difference by the spread of paired differences. The p-value indicates how unusual the result would be under no average difference; smaller values are less compatible with that assumption. Holm correction adjusts the 36 p-values to limit false positives across the full set. A nonsignificant result is not evidence of equivalence.

What the preserved evidence says

  • The original is a user-supplied inline assignment excerpt; the exact original provider response, provider identity, and generation settings remain unauthenticated.
  • The separate archived Gemini run was not substituted for these versions. Its recorded metadata conflicts with the Phase 2 Argon 4 Medium label.

How it was done

Research question

Can a model write useful weights directly?

Experiment 5 asks whether a language model can specify the numbers in a neural network policy that plays MinAtar Breakout, without training that policy through rewards or gradient updates. This repository evaluates fixed weight files after they have been generated.

Game environment

MinAtar Breakout

The board is 10 × 10. The paddle occupies one cell on the bottom row. A ball moves diagonally; bricks fill rows 1–3 and each destroyed brick adds one point. A missed ball ends an episode. The environment uses sticky actions with probability 0.1 and a 10,000-step cutoff.

What the network sees

MinAtar’s native state has paddle, ball, trail, and brick channels. The experiment maps these into six channels in a 10 × 10 × 6 observation: paddle, empty danger, bricks, ball, trail, empty gauge. Row-major flattening uses (row × 10 + column) × 6 + channel, giving 600 binary inputs. The six actions are no-op, left, up, right, down, and fire; only left and right move the paddle.

Policy architecture

600 → 32 → 32 → 6

Each fixed network has two hidden layers with 32 units each. The hidden layers use the tanh function; the final layer outputs six action scores. That is 20,486 parameters including biases. A stable softmax turns scores into probabilities, and an action is sampled from that distribution.

Original generations

Recorded model conditions

The five primary conditions are Gemini Argon 4 Medium, Claude Sonnet 5.5, GPT-6 Original, GPT-6 Luna Extra High, and DeepSeek Original. Their original prompt copies, captured responses, parsed weight archives, and local metadata are preserved in the repository. The prompt is available here.

Provider names, model identifiers, one-shot status, tool settings, and reasoning effort are shown as recorded metadata. The independent audit found no provider-side attestations that authenticate those labels.

The Astra file is a reference controller. PPO is a trained reinforcement-learning baseline. Random-action and zero-weight policies are controls. DeepSeek Corrected is a later researcher intervention and must not be merged with original zero-shot generations.

Corrected local protocol

27,000 evaluation episodes

Nine conditions were evaluated for 3,000 episodes each, using seed groups 42, 100, and 200 with 1,000 episodes per group. The same base seeds and derived seed triplets were used across conditions. The evaluator creates separate environment and policy streams with numpy.random.SeedSequence(base_seed).spawn(2); MinAtar and categorical policy sampling each receive their own RandomState.

For each condition, the report includes mean, sample standard error, median, range, episode length, cutoff frequency, and selected/executed action counts. Paired comparisons use matched episode seeds, percentile bootstrap confidence intervals, two-sided sign-flip permutation tests, paired Cohen’s dz, and Holm correction over 36 comparisons. Nonsignificant comparisons are not equivalence evidence.

The corrected local evaluation is not the original paper’s sample: it uses 3,000 episodes rather than the reported 1,000, and uses a separated RNG protocol. Historical and corrected score differences combine that protocol change with different random draws.

Separate development experiment

Argon High — iterative development

The experiment evaluates the inline original assignments and two separate researcher-directed follow-up scripts, 3,000 matched episodes per version. The follow-up versions are interventions during development; they are not independent zero-shot generations and do not replace Gemini Argon 4 Medium in the five-condition primary set. The network has the same 600 → 32 → 32 → 6 architecture. The paired analysis reports small effect sizes; the nonsignificant Follow-up 1 vs Follow-up 2 result does not establish equivalence.

All 9,000 episodes ended by ball loss with no time-limit cutoffs. The original provider response and identity remain unauthenticated, and the repository's separate archived Gemini run has metadata that conflicts with the Phase 2 Argon 4 Medium label. The supplied Follow-up 2 verifier contains an impossible float64 probability assertion; a separate 7,280-state comparison agreed with its own oracle, but this is not a proof about all MinAtar states. The full report and raw episode files are linked from Results.

Independent check

Phase 3 verdict: Verified with limitations

The audit independently checked the Phase 2 repository state, protected artifact hashes, corrected CSV summaries, matched-seed calculations, selected replay traces, and RNG separation. The raw metrics reproduced from the episode CSVs.

  • Model/provider identity and some generation settings remain recorded metadata without independent authentication.
  • The GUI test failures remained unresolved: six failed and three errored during Tk startup, before the GUI assertions ran.
  • One generation per model and one environment do not support broad capability or reliability claims.
  • The browser arena is a new educational port and is not benchmark-equivalent unless its conformance checks pass.

See the Phase 2 report and registry in the research repository for source artifacts.

People and tools

Recorded contributions

The repository describes the work as a human-led research effort supported by AI coding and model-generation tools. It preserves the task prompt, captured model responses, parsed weights, evaluator, and later audit changes. The model outputs are the experimental objects; they are not trained during evaluation.

Project documents identify some model/tool roles, but they do not independently establish provider identity or give a verified, line-by-line attribution of who implemented each component. This site therefore reports contributions at the level supported by those records and does not claim that a researcher personally implemented or understood every technical component.

Limits of the evidence

What these results can and cannot show

The evidence concerns five fixed generations, one small architecture, one game, and one corrected local evaluation. It can describe how these particular archived networks performed under this protocol. It cannot establish model-wide capability, reliable repeatability across independent generations, or performance in other tasks.

The Astra policy is handcrafted/reference, PPO is trained, and random/zero-weight conditions are controls. DeepSeek Corrected is a post-hoc intervention. Keep each category distinct when interpreting the ranking.
